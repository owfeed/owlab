# owlab

[English](README.md)

owlab запускает одноразовые роутеры OpenWrt и ImmortalWrt. Один файл, одна команда, работающие
роутеры на Linux, WSL2, Docker Desktop для Windows или macOS.

- **Зачем:** разрабатывать пакет LuCI сразу на нескольких релизах. Проверить конфиг до того, как он
  попадёт на роутер, от которого зависит дом. Снять скриншоты или понять, что делает настройка.
- **В CI:** отвечает на вопрос «мой пакет всё ещё ставится на 24.10?» за [один шаг](#проверять-в-ci).
- **Нужно:** Docker (или OrbStack, Colima, Podman, Rancher Desktop) с Compose v2. QEMU только для
  `fidelity: vm`.
- **Не только разрабатываете пакет, но и выпускаете?** [Кукбук](https://owfeed.org/cookbook/ru/)
  проходит весь путь (собрать, проверить, подписать, опубликовать) с готовыми файлами.

## Быстрый старт

1. Поставьте owlab и проверьте машину. `go install` нужен Go 1.25.3 или новее. Другие способы:
   [Установка](#установка).

   ```console
   $ go install owfeed.org/owlab/cmd/owlab@latest
   $ owlab doctor
   ```

2. Положите `owlab.yaml` рядом со своим пакетом:

   ```yaml
   version: 1

   routers:
     - id: owrt2512
       release: "25.12.5"
   ```

3. Запустите роутер:

   ```console
   $ owlab up
     owrt2512   http://localhost:8080   ssh -p 2222 root@localhost
   ```

4. Откройте адрес. Логин `root`, пароль оставьте пустым.

5. Соберите пакет и проверьте его на роутерах из `owlab.yaml`:

   ```console
   $ owlab build
   $ owlab test --install 'dist/*/luci-app-mine-*' \
       --assert 'http 200 /cgi-bin/luci/admin/services/mine'
   ```

   - `owlab test` поднимает роутеры, ставит пакет, выполняет ассершен, сносит роутеры и возвращает
     0 или 1.
   - Без `owlab.yaml` назовите релизы: `owlab test --release 25.12.5 …` создаёт по роутеру на релиз.
   - Что принимают `--install` и `--assert`: [Проверять в CI](#проверять-в-ci).

## Установка

Нет тулчейна Go? Возьмите бинарь из
[последнего релиза](https://github.com/owfeed/owlab/releases/latest) и положите в `PATH`.

- Есть сборки для linux, darwin и windows, amd64 и arm64.
- На Windows это PowerShell и `owlab.exe`. Больше ничего не нужно.
- Для `fidelity: vm` поставьте QEMU: `brew install qemu`,
  `apt install qemu-system-arm qemu-system-x86` или
  `winget install SoftwareFreedomConservancy.QEMU`.
- Что нужно каждой платформе (правило про файловую систему WSL2, два необязательных компонента
  Windows, группа `kvm` на Linux), собрано в одном разделе
  [ранбука](docs/runbook_ru.md#поставить-owlab-на-эту-машину).

`owlab doctor` проверяет всё это и говорит, чем грозит каждое отсутствующее.

## Рецепты

### Проверять на нескольких релизах сразу

```yaml
routers:
  - id: owrt2512
    release: "25.12.5"
  - id: owrt2410
    release: "24.10.8"
  - id: imm2512
    distro: immortalwrt
    release: "25.12.1"
```

owlab назначает порты по позиции в `routers:`. Первый роутер получает HTTP 8080 и ssh 2222, второй —
8081 и 2223, и так далее. `owlab status` их показывает. Задать свои: `ports: { http: 8025, ssh: 2225 }`.

### Добавить пакеты

На роутере уже есть то, что стоит на серийном устройстве с OpenWrt. Добавляйте поверх через `+`:

```yaml
defaults:
  packages: ["+luci-app-sqm", "+luci-app-ddns"]
```

Убрать через `-`:

```yaml
packages: ["-ppp", "-ppp-mod-pppoe", "+luci-app-sqm"]
```

Список без `+` и `-` заменяет набор по умолчанию целиком.

Поставить пакет без пересборки:

```console
$ owlab install owrt2512 luci-app-ttyd
```

Он исчезнет после `owlab up --rebuild`. `packages:` сохраняется.

### Поставить пакет, которого нет ни в одном фиде

Свой собственный или что угодно с GitHub Releases. Укажите оба URL, потому что apk и opkg называют
файлы по-разному:

```yaml
defaults:
  extra_packages:
    - name: luci-app-example
      apk: https://github.com/someone/example/releases/download/1.4.0/luci-app-example-1.4.0-r1.apk
      ipk: https://github.com/someone/example/releases/download/1.4.0/luci-app-example-v1.4.0-r1-all.ipk
```

- Пиньте точный релиз.
- owlab ставит эти пакеты без проверки подписей.

### Работать над пакетом на живом роутере

```console
$ owlab sync
  owrt2512   42 files, 846 KB
```

Перезагрузите страницу, и правки на месте. Чтобы синхронизировать на каждое сохранение:

```console
$ owlab sync --watch
```

owlab копирует те же каталоги, что ставит `luci.mk`: `htdocs`, `ucode`, `luasrc`, `root`. Если
пакет лежит в подкаталоге, скажите об этом:

```yaml
project:
  install:
    my-package/htdocs: /www
    my-package/ucode:  /usr/share/ucode/luci
    my-package/root:   /
```

### Собирать ассеты перед каждым sync

Это нужно, если пакет генерирует файлы, которых нет в дереве: `cascade.css` темы,
скомпилированные переводы, JS-бандл.

```yaml
project:
  build: ./build-css.sh htdocs/luci-static/footstrap/cascade.css
```

### Выполнить что-то на роутере после каждого sync

Так регистрируют пакет, сбрасывают кеш или перезапускают сервис.

```yaml
project:
  post_sync: |
    uci -q set luci.themes.Footstrap=/luci-static/footstrap
    uci -q commit luci
```

### Работать над темой

```yaml
project:
  theme: footstrap
```

owlab выбирает тему после каждого sync.

- Без этого тема зарегистрирована, но не показана. Установка пакета темы добавляет
  `luci.themes.<Name>` и намеренно не трогает `luci.main.mediaurlbase`.
- [examples/luci-theme-footstrap](examples/luci-theme-footstrap/owlab.yaml) — настоящий пример:
  четыре роутера, шаг сборки для генерируемого CSS и приложения не из фида, на которых проверяется
  каскад.

### Грузить модули ядра или получить настоящий WiFi

```yaml
routers:
  - id: real
    fidelity: vm
    release: "25.12.5"
    packages: ["+kmod-nft-tproxy"]
```

```console
$ owlab up
$ owlab exec real -- 'uname -r; lsmod | grep nft_tproxy'
6.12.94
nft_tproxy    12288  0
```

Этот роутер — QEMU с собственным ядром OpenWrt, поэтому пакеты `kmod-*` грузятся.

- **WiFi:** он получает два радио `mac80211_hwsim`, и они работают. Запускается hostapd, iwinfo
  отдаёт сигнал и ширину канала, страницы Wireless показывают роутер вместо его конфига.
- **Время старта:** первый раз около полутора минут, дальше двадцать секунд.
- **Диск:** хранит всё установленное и переживает `owlab down`.
- **Настройки:** `memory: 512M`, `cpus: 2`, `disk: 2G`, `radios: 2`. `radios: 0` — без
  беспроводного.

### Сделать коробку обжитой

Пустой роутер почти ничего не рисует: ни бейджей зон, ни VLAN, ни аренд DHCP, ни таблиц со
строками. Фикстуры всё это выдумывают:

```yaml
defaults:
  fixtures: [all]
```

- Отдельные профили: `networks`, `clients`, `wireguard`, `portforwards`, `system`, `wifi`.
- `lived-in` — всё, кроме wifi, и он по умолчанию.
- `none` выключает фикстуры.

### Собрать настоящий .apk или .ipk

```console
$ owlab build
$ owlab install owrt2512 dist/noarch/luci-app-mine-1.0-r1.apk
```

`owlab build` работает через SDK от OpenWrt. Делайте это перед релизом: настоящая сборка
минифицирует JS и CSS, sync этого не делает. На этой разнице ломались пакеты, прекрасно работавшие
на дев-боксе.

Архитектурно независимый пакет попадает в два каталога:

```
dist/
├── noarch/luci-app-mine-1.0-r1.apk
└── all/luci-app-mine_1.0-r1_all.ipk
```

`--layout flat` возвращает прежний плоский вывод.

<details>
<summary>Почему вывод разложен по архитектурам</summary>

Артефакты кладутся в каталог, названный по архитектуре: в имени apk-файла архитектуры нет вообще,
и всё, что идёт дальше, читает каталог. Архитектурно независимый пакет даёт оба написания: apk
требует `noarch` и отвергает `all`, opkg знает только `all`. Поэтому одна сборка пишет два каталога.

Эта раскладка — [контракт артефакта owfeed][artifact-contract]. Она позволяет отдать вывод
`owlab build` инструменту публикации напрямую, и при этом они не знают друг о друге.

</details>

[artifact-contract]: https://github.com/owfeed/owfeed/blob/main/docs/artifact-contract.md

### Проверять в CI

```yaml
- uses: owfeed/owlab/action@v0.7.1
  with:
    releases: "25.12.5 24.10.8"
    install: dist/*/luci-app-mine-*
    assert: |
      http 200 /cgi-bin/luci/admin/services/mine
      service mined
      uci mine.@mine[0].enabled
```

- `owlab.yaml` не нужен: конфигурация — это номера релизов.
- Шаг setup не нужен: экшен ставит бинарь owlab сам.
- Джоб падает, если пакет не поставился, страница не отрисовалась или сервис не поднялся. В summary
  написано, какой роутер и какая проверка.

То же самое локально — и ровно это запускает экшен:

```console
$ owlab test --release 25.12.5 --release 24.10.8 \
    --install 'dist/*/luci-app-mine-*' \
    --assert 'http 200 /cgi-bin/luci/admin/services/mine'
```

- Поднять, поставить, проверить, снести, вернуть 0 или 1.
- `--keep` оставляет роутеры поднятыми. `--json` пишет отчёт в stdout.
- owlab печатает лог упавшего роутера, пока контейнер ещё существует.
- Полный список ассершенов и формат JSON: [docs/reference_ru.md](docs/reference_ru.md#owlab-test).

<details>
<summary>Две вещи, которых не делает написанный руками <code>curl</code></summary>

Он **логинится в LuCI под root**. Каждая страница, ради которой существует приложение, лежит под
`/cgi-bin/luci/admin`, и неавторизованный запрос туда — это редирект на форму логина. Поэтому
очевидная проверка отдаёт 403 на здоровой странице.

Он **валит 200, чьё тело — страница ошибки**. Поймав исключение, диспетчер LuCI всё равно отвечает
200 и кладёт трейс в тело.

</details>

### Проверить установку из фида

```console
$ owlab test --release 25.12.5 \
    --feed 'https://example.org/releases/25.12/x86_64/packages.adb' \
    --feed-key ./myfeed.pem \
    --install my-app \
    --assert 'http 200 /cgi-bin/luci/admin/services/mine'
```

- Имя, которое ставится через `--feed`, ставится без `--allow-untrusted`, так что подпись индекса
  обязана сойтись. На apk файл из `--install` ставится с этим флагом: у локально собранного пакета
  нет подписи, которую знает роутер.
- Для opkg *имя* файла ключа обязано быть его id: opkg ищет ключ по имени.

<details>
<summary>Зачем проверять из фида, если установка файла проходит</summary>

Установка файла доказывает, что работает пакет. Установка **по имени** из подписанного индекса
доказывает, что работает канал. Индекс читается, URL не редиректит, ключ на роутере совпадает с
тем, которым подписано. Установка файла не может провалиться ни по одной из этих причин, значит и
обнаружить их не может.

</details>

### Попасть на роутер

```console
$ owlab shell owrt2512
$ owlab exec owrt2512 -- 'logread | tail -20'
$ owlab logs owrt2512 -f
$ owlab open owrt2512
```

`ssh -p 2222 root@localhost` тоже работает. owlab ставит все найденные `~/.ssh/id_*.pub`. Указать
другой: `OWLAB_PUBKEY=/path/to/key.pub`.

### Задать пароль root

```console
$ OWLAB_ROOT_PASSWORD=hunter2 owlab up --rebuild
```

По умолчанию пароля нет. Для коробки на localhost это нормально, и LuCI принимает пустое поле.

### Держать конфиг в другом месте

```console
$ owlab --config ../my-package/owlab.yaml up
$ owlab --config ../my-package status        # каталог тоже подойдёт
$ export OWLAB_CONFIG=~/src/my-package
```

Без этого owlab ищет в текущем каталоге и выше. В [examples/](examples/) лежат конфиги, на которые
можно указать напрямую.

### Узнать, не устарели ли пины

```console
$ owlab releases
ROUTER          DISTRO    PINNED     NEWEST
owrt2512        openwrt   25.12.4    25.12.5    1 release behind
owrt2410        openwrt   24.10.8    24.10.8    up to date
```

- `owlab releases --all` покажет всё, что публикуют серверы загрузок.
- Пиньте точные точечные релизы и двигайте их осознанно. Rootfs и его фид обязаны называть один
  релиз. Смешение роняет любую установку с `breaks: world[...]`.

### Начать с нуля

```console
$ owlab up --rebuild        # выбросить роутеры и собрать заново
$ owlab down --purge        # и снести образы с дисками VM
```

## Команды

```
owlab up          собрать и запустить роутеры
owlab down        остановить роутеры
owlab sync        скопировать пакет и перезагрузить LuCI
owlab shell       открыть шелл
owlab exec        выполнить команду
owlab install     поставить пакеты на работающий роутер
owlab build       собрать настоящий .apk/.ipk через SDK
owlab test        поднять, поставить, проверить, снести — один код выхода
owlab logs        лог загрузки и сервисов
owlab releases    сверить пины с серверами загрузок
owlab status      что запущено и где
owlab open        открыть LuCI в браузере
owlab doctor      проверить эту машину
owlab version     показать версию owlab
```

- Любая команда принимает id роутеров. Без них действует на все.
- `--config <path>` (или `-c`) работает с любой из них, до и после имени команды.
- У `test`, `status` и `releases` есть `--json`.

## Когда что-то сломалось

1. Запустите `owlab doctor`. Он проверяет порты, ssh-ключи, окончания строк, QEMU и то, пропускает
   ли ваш движок DNS.
2. Найдите симптом в [docs/troubleshooting_ru.md](docs/troubleshooting_ru.md). Почти всё, что здесь
   ломается, выглядит как что-то другое: роутер, который отдаёт LuCI, но сбрасывает каждое
   соединение; пакет, который поставился и ничего не делает; радио, которые существуют, но не
   поднимаются. Страница отсортирована по симптомам.
3. Процедуры — в [docs/runbook_ru.md](docs/runbook_ru.md): задача, команды и как убедиться, что
   вышло.

## Безопасность

- Логин `root` с пустым паролем, если вы не задали свой.
- Хост-ключи ssh вшиты в образ и общие у всех, кто им пользуется. Не выставляйте эти роутеры в
  сеть, которая вам дорога́.
- Пиньте точные точечные релизы. Образы и фиды `snapshot` пересобираются ежедневно и независимо,
  так что установки начинают падать в течение суток.

## Рядом с чем это стоит

- **[containerlab](https://containerlab.dev/)** строит топологии: много узлов, линки между ними.
  Он поддерживает OpenWrt как вид узла. owlab строит один роутер, под который вы пишете: топологии
  нет, зато есть `sync` с горячей перезагрузкой, фикстуры, сборка через SDK и `test`. Два роутера,
  гоняющих BGP друг в друга, — это containerlab. Одна и та же страница LuCI, открытая на 24.10 и
  25.12, пока вы её правите, — это owlab.
- **[owfeed](https://github.com/owfeed/owfeed)** публикует пакеты. Он собирает, подписывает и
  индексирует apk-фид, а `owfeed smoke` ставит результат на живой образ OpenWrt перед публикацией.

<details>
<summary>Как owlab и owfeed остаются независимыми</summary>

`owfeed smoke` тоже поднимает контейнер, и сходство намеренное: owlab — это цикл разработки,
`owfeed smoke` — одна проверка перед публикацией. Они независимы специально, чтобы ответ на
«поставится ли фид» никогда не зависел от того, правильно ли установлен owlab.

При этом они стыкуются через формат файлов, без зависимости друг от друга. `owlab build` пишет
`dist/<arch>/`, и каждая стадия owfeed его читает. owlab никогда не держит ключей, и в этом вся его
сторона границы. Он утверждает, что пакет работает, и никогда — что ему стоит доверять.

Граница и контракты через неё записаны в
[ECOSYSTEM.md](https://github.com/owfeed/owfeed/blob/main/docs/ECOSYSTEM.md).
[docs/STATUS.md](docs/STATUS.md) говорит, сколько из стороны owlab уже есть.

</details>

накладывает на ваш код ничего. Обязательства возникают при распространении изменённого owlab.

<details>
<summary>Почему GPL-2.0-only</summary>

[owfeed](https://github.com/owfeed/owfeed) того же автора под Apache-2.0. owlab встраивает оверлей
из `/etc/uci-defaults` и `rc.local`, написанный поверх шелл-библиотек самого OpenWrt. Этот оверлей
лежит внутри каждого собираемого образа; это производная работа.

</details>

OpenWrt — зарегистрированный товарный знак Software Freedom Conservancy. owlab не аффилирован с
проектом OpenWrt или SFC и ими не одобрен.
