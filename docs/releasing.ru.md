# Релизы

[English](releasing.md)

## Выпуск версии

Сдвиньте заголовок `## [Unreleased]` в `CHANGELOG.md` до версии с датой,
добавьте ссылку сравнения внизу файла, затем:

```console
$ git tag -a v0.2.0 -m 'owlab 0.2.0'
$ git push origin v0.2.0
```

Это вся процедура. Тег — единственный вход: из него берутся версия в бинаре,
имена архивов, заголовок релиза и его тело.

Релиз падает, если в `CHANGELOG.md` нет секции под эту версию. Тег, под который
никто не написал запись, не должен публиковать пустую страницу.

## Что делает тег

`release.yml` собирает пять архивов — linux/amd64, linux/arm64, darwin/amd64,
darwin/arm64, windows/amd64 — в каждом бинарь, README, changelog, лицензия и
`docs/`. Затем пишет `SHA256SUMS`, публикует релиз **черновиком** и отдельным
шагом переводит его в опубликованные.

Черновик здесь важен. `releases/latest` сдвигается в момент публикации, а
экшн загрузки сначала создаёт релиз и только потом заливает ассеты — так что у
релиза, опубликованного сразу, есть окно, в котором `latest` указывает на
пустоту. Черновик не является `latest`, поэтому переключение происходит один
раз, когда всё уже на месте.

Последний шаг скачивает `releases/latest/download/SHA256SUMS` и сверяет с тем,
что только что собрано. 404 здесь означает, что все скачивания провалились бы, и
это последний момент, когда это красная сборка, а не баг-репорт.

`softprops/action-gh-release` запинен по коммиту, а не по тегу `v3`. Это
единственный сторонний экшн в репозитории, и он работает в единственной джобе,
которая может писать в релиз, — то есть тот, кто может сдвинуть этот тег, может
публиковать ассеты под нашим именем.

## Номера версий

Semver, где поверхностью совместимости служит `owlab.yaml`. Конфиг
`version: 1`, работающий сегодня, продолжит работать на минорных и патч-релизах;
изменение, которое его сломает, ждёт мажорного.

Бинарь отвечает тремя способами, в порядке предпочтения:

1. Тем, что застемпила релизная сборка через `-ldflags -X main.version=…`.
2. Тем, что записала модульная система, — так `go install …@v0.2.0` знает свою
   версию.
3. `dev` — для обычного `go build` из чекаута.

Коммит и дата сборки приходят либо из стемпа, либо из VCS-информации, которую
вшивает тулчейн Go, так что `owlab version` говорит правду в любом случае. Здесь
это важнее, чем в большинстве инструментов: owlab несёт контекст сборки образов
внутри бинаря, поэтому «какой owlab собрал этот роутер» — реальный вопрос.

Дата сборки — дата коммита, не стенные часы. Пересборка того же тега должна
давать тот же файл.

## Образы роутеров

`images.yml` публикует в `ghcr.io/vizzletf/owlab-rootfs`. Один тег — один
таргет: дистрибутив, точный релиз, архитектура. В OCI image index нет поля под
«версию дистрибутива», а у большинства имён архитектур OpenWrt нет валидного
GOARCH-соответствия. Manifest list такую матрицу не выражает, и апстрим тоже не
пытается.

Запускается еженедельно, на пушах, задевающих входы образов, и после релиза.

### Слежение за апстримом

`images/owlab.yaml` пинит один релиз на ветку. Этот пин получает разработчик,
собирающий локально, и он же служит полом: публикуется `keep` последних точечных
релизов тех же веток, вычисленных на сервере загрузок во время сборки.

Так апстрим, тегнувший 25.12.5, кладёт образ на GHCR в ближайший понедельник
без того, чтобы кто-то правил номер версии, а 25.12.4 остаётся доступным для
тех, кто ещё не переехал. `keep` по умолчанию 2 и является входом и для ручного
запуска, и для вызова из релиза.

Две вещи, которые резолвер проверяет и о которых листинг не говорит:

- **У релиза действительно есть артефакты для таргета.** Точечный релиз
  появляется в листинге, когда его тегнули; образы конкретного таргета — когда
  закончилась его сборка. Поверив листингу на слово, получаем джобу, которая
  падает на 404 через двадцать минут.
- **Запиненный релиз собирается всегда**, даже если он выпал из окна. Кто-то
  пинит его в собственном `owlab.yaml`, и еженедельная пересборка — то, что
  держит этот образ в тонусе со своим фидом.

Если сервер загрузок прочитать не удалось, матрица откатывается на пины. Джоба
публикации, упавшая из-за таймаута листинга, была бы хуже той, что опубликовала
то, что уже написано в конфиге.

Посмотреть текущее положение дел:

```console
$ cd images && owlab releases
```

### Неизменяемые теги

Релиз добавляет второй тег рядом с плавающим:

```
ghcr.io/vizzletf/owlab-rootfs:openwrt-25.12.5-x86_64          двигается
ghcr.io/vizzletf/owlab-rootfs:openwrt-25.12.5-x86_64-v0.2.0   нет
```

Плавающий тег пересобирается еженедельно и подхватывает изменения фида внутри
того же запиненного релиза, так что разрабатывать против него правильно, а
пинить — нет. Указывайте `image:` на версионный, когда нужны те же байты дважды.

## Ничего никогда не удаляется

Старые образы остаются на GHCR. Чей-то `owlab.yaml` на них ссылается, а тег,
переставший резолвиться, — это сломанная сборка у постороннего человека.
Резолвер перестаёт **собирать** старые релизы, но не удаляет их.
