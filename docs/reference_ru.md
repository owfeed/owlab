# Справочник по конфигурации

[English](reference.md)

Все ключи `owlab.yaml`, все переменные окружения и флаги всех команд `owlab`.
Для того, у кого есть проект owlab и нужно найти одно значение.

- Шаги под задачу («как сделать X») — в [ранбуке](runbook_ru.md).
- Почему дефолты именно такие — во [внутренностях](internals_ru.md).
- Роутеру нужны только `id` и `release`. У всего остального есть дефолт.
- Список пакетов с `+`/`-` применяется поверх дефолтов. Список без префиксов их заменяет.

## Пример owlab.yaml

```yaml
version: 1

project:
  name: luci-theme-example        # по умолчанию имя каталога
  theme: example                  # для тем: активировать после sync
  install:                        # по умолчанию — маппинг из luci.mk
    htdocs: /www
    ucode:  /usr/share/ucode/luci
    luasrc: /usr/lib/lua/luci
    root:   /

defaults:                         # вливается в каждый роутер
  fidelity: basic
  arch: auto                      # совпадает с хостом, без эмуляции
  packages: ["+luci-app-sqm"]     # поверх стокового набора, см. ниже

routers:
  - id: owrt2512
    distro: openwrt               # openwrt | immortalwrt
    release: "25.12.5"
    packages: ["+luci-app-sqm"]   # + добавляет, - убирает
    ports: { http: 8025, ssh: 2225 }

  - id: real                      # только для fidelity vm:
    fidelity: vm
    release: "25.12.5"
    memory: 512M                  # qemu -m
    cpus: 2                       # qemu -smp
    disk: 2G                      # диск extroot; 0 — использовать свой оверлей образа
    radios: 2                     # радио mac80211_hwsim; 0 — без беспроводного
    ports: { http: 8090, ssh: 2290 }
```

## Поля owlab.yaml

`defaults:` принимает любой ключ роутера. Его значения вливаются в каждый роутер, а собственное
значение роутера побеждает.

| Поле | Что делает | Значения | По умолчанию | Пример |
|---|---|---|---|---|
| `version` | Версия формата конфига | `1` | `1` | `version: 1` |
| `project.name` | Имя проекта | строка | имя каталога | `luci-theme-example` |
| `project.theme` | Тема, которая активируется при первой загрузке и после каждого синка. См. [Темы](#темам-нужен-ещё-один-шаг) | имя медиакаталога | нет | `footstrap` |
| `project.install` | Сопоставляет исходный каталог с местом назначения на роутере. См. [Что копирует `sync`](#что-копирует-sync-и-с-какими-правами) | словарь каталог → путь | маппинг из luci.mk | `htdocs: /www` |
| `project.build` | Командная строка шелла: выполняется на хосте, в каталоге проекта, перед каждым синком | строка | нет | `./build-css.sh …` |
| `project.post_sync` | Командная строка шелла: выполняется на каждом роутере после того, как файлы приехали | строка | нет | `uci -q commit luci` |
| `project.lock` | Файл блокировки для каждого роутера; `{id}` — id роутера | путь относительно каталога `owlab.yaml` | `.owlab/locks/{id}.lock` | `../tmp/stands-{id}.lock` |
| `routers[].id` | Имя роутера для всех команд | строка | обязательно | `owrt2512` |
| `distro` | Дистрибутив | `openwrt`, `immortalwrt` | `openwrt` | `immortalwrt` |
| `release` | Точный точечный релиз. См. [Пиньте точные точечные релизы](#пиньте-точные-точечные-релизы) | точечный релиз или `snapshot` | обязательно | `"25.12.5"` |
| `arch` | Архитектура. См. [Архитектура](#архитектура) | `auto` или package-архитектура OpenWrt | `auto` | `x86_64` |
| `fidelity` | Контейнер или виртуальная машина QEMU | `basic`, `vm` | `basic` | `vm` |
| `image` | Готовый образ, с которого стартовать. См. [Готовые образы](#готовые-образы) | ссылка на образ | опубликованный образ owlab | `ghcr.io/owfeed/owlab-rootfs:openwrt-25.12.5-x86_64` |
| `packages` | Пакеты из фидов. См. [Стоковый набор пакетов](#стоковый-набор-пакетов) | список; `+имя` добавляет, `-имя` убирает, без префикса — заменяет | стоковый набор | `["-ppp", "+luci-app-sqm"]` |
| `extra_packages` | Пакеты, скачанные по URL. См. [Пакеты, которых нет ни в одном фиде](#пакеты-которых-нет-ни-в-одном-фиде) | список из `name`, `apk`, `ipk` | нет | см. раздел |
| `fixtures` | Профили выдуманного конфига. См. [Фикстуры](#фикстуры) | имена профилей, `lived-in`, `all`, `none` | `lived-in` | `[all]` |
| `ports` | Порты хоста, проброшенные на роутер | `http`, `ssh` (целые) | `8080` и `2222` плюс индекс роутера в списке | `{ http: 8025, ssh: 2225 }` |
| `hostname` | Имя хоста роутера | строка | `id`, где `_` и `.` заменены на `-` | `owrt2512` |
| `package_manager` | Переопределяет пакетный менеджер | `apk`, `opkg` | выводится из дистрибутива и релиза | `opkg` |
| `memory` | Память VM, передаётся в `qemu -m`. Только `fidelity: vm` | размер | `512M` | `512M` |
| `cpus` | Процессоры VM, передаются в `qemu -smp`. Только `fidelity: vm` | целое | `2` | `2` |
| `disk` | Размер второго диска, который монтируется как `/overlay` (extroot). Только `fidelity: vm` | размер, либо `0` / `none` — использовать свой оверлей образа | `2G` | `2G` |
| `radios` | Число радио `mac80211_hwsim`. Только `fidelity: vm` | целое; `0` — без беспроводного | `2` | `2` |

## Что копирует `sync` и с какими правами

- **Маппинг.** `project.install` сопоставляет исходный каталог с местом назначения на роутере. По
  умолчанию это собственный маппинг luci.mk. Пакету, разложенному принятым способом, блок `install:`
  не нужен.
- **Не синкается никогда.** `/etc/config/` и `/etc/uci-defaults/` пропускаются намеренно.
- **`0755`.** Всё под `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/libexec`, `/etc/init.d`,
  `/etc/rc.d`, `/etc/hotplug.d` и `/etc/cron.d`, а также всё, что начинается с `#!`.
- **`0644`.** Всё остальное.

Права выводятся из места назначения и содержимого файла. Права файла на вашем диске не учитываются. Это те же два
режима, что у luci.mk, поэтому у синканутого дерева права те же, какие поставил бы собранный пакет.

<details>
<summary>Почему <code>/etc/config/</code> пропускается, а права выводятся</summary>

`/etc/config/` и `/etc/uci-defaults/` — состояние роутера. Пакету они не принадлежат. Настоящая установка кладёт их
как conffiles и не трогает уже существующие. Перезапись на каждом синке выбрасывала бы всё, что вы
настроили на роутере.

Вывод прав вместо копирования делает синк одинаковым на любом хосте. На Windows бита исполнения нет
вообще, и любой файл отдаётся как `0666`. Диск Windows, примонтированный в WSL, отдаёт всё как `0777`.
Перенос любого из двух давал роутер, который вёл себя по-разному в зависимости от машины, откуда
синкали.

Ни один из отказов не называет права: procd сообщает о неисполняемом init-скрипте как о
несуществующем сервисе.

</details>

## `project.build` и `project.post_sync`

```yaml
project:
  build: ./build-css.sh htdocs/luci-static/footstrap/cascade.css
  post_sync: |
    uci -q set luci.themes.Footstrap=/luci-static/footstrap
    uci -q commit luci
```

| Ключ | Где выполняется | Когда | Шелл |
|---|---|---|---|
| `build` | на хосте, в каталоге проекта | перед каждым синком | `sh`; на Windows — `sh.exe` из Git for Windows или другой POSIX-шелл в `PATH` |
| `post_sync` | на каждом роутере | после того, как файлы приехали, и до сброса кешей LuCI | busybox ash роутера |

- Оба — командные строки шелла. Строка отдаётся шеллу и не режется по пробелам, поэтому пайп,
  редирект или `&&` работают.
- На Windows `sh` ничем не подменяется. Отдать POSIX-строку в `cmd.exe` значит тихо выполнить не то.
- `owlab doctor` сообщает, есть ли такой шелл и указывает ли `build` на программу, которую он может
  найти.

## Стоковый набор пакетов

Роутер вообще без `packages:` получает то, что установлено на серийном устройстве с OpenWrt. Это не
голый rootfs.

Набор — собственные `DEFAULT_PACKAGES` и `DEFAULT_PACKAGES.router` OpenWrt из `include/target.mk`.
Сверху идёт то, что firmware-selector добавляет для беспроводного роутера с LuCI:

```
base-files ca-bundle dropbear fstools libc libgcc logd mtd netifd uci
uclient-fetch urandom-seed urngd
dnsmasq firewall4 nftables kmod-nft-offload odhcp6c odhcpd-ipv6only ppp
ppp-mod-pppoe
wpad-basic-mbedtls wifi-scripts
luci luci-app-firewall luci-app-attendedsysupgrade luci-app-package-manager
```

Убрать что угодно через `-`:

```yaml
packages: ["-ppp", "-ppp-mod-pppoe", "+luci-app-sqm"]
```

Два осознанных отступления от списка реального устройства:

- **`libustream-mbedtls` не назван**, хотя в апстримном списке он есть.
- **Ничего платформенного:** `fitblk`, `uboot-envtools`, `kmod-usb3`, `kmod-leds-gpio`,
  `kmod-gpio-button-hotplug`, `kmod-crypto-hw-safexcel`, `kmod-mt7915e` и прошивки mt7986. Если
  разрабатываемому пакету нужен один из них на диске для разрешения зависимости, добавьте его в проект.

<details>
<summary>Почему набор перечислен явно и откуда отступления</summary>

Бо́льшая часть набора уже есть в апстримном тарболе, так что установка обычно ничего не делает.
Перечисление всё равно имеет смысл: набор становится свойством owlab. От того, какой тарбол
дистрибутив решил опубликовать, он не зависит. Форк с более тощим rootfs получает тот же роутер.

TLS-бэкенд — выбор времени сборки. В каждом образе уже есть тот вариант, с которым он собран, и
просьба к ImmortalWrt 24.10 поставить mbedtls-вариант отклоняется.

Платформенные пакеты описывают разметку флеша, загрузчик, светодиоды и радиокремний одной коробки. Без
этого железа они не работают, а у контейнера нет своего ядра, чтобы их загрузить.

Беспроводная пара в наборе не ради радио. LuCI гейтит всё меню Network → Wireless на
`access('/sbin/wifi')`, который приходит из `wifi-scripts`. Матрицу шифрования LuCI строит, спрашивая у
`hostapd`, что тот поддерживает. С этими двумя страницы рисуются из конфига, без единого радио.

</details>

### Когда пакет не ставится

Набор ставится одним вызовом. Исходы:

| Случай | Результат |
|---|---|
| Имени нет в фидах релиза | Пропуск одной строкой, не ошибка. Имя убирается, остальное запрашивается снова одним вызовом |
| На opkg имя даёт пакет, уже стоящий на роутере | Пропуск, имя так же убирается из вызова. apk сам считает такой пакет нужным именем |
| Вызов не прошёл по другой причине | Каждый пакет ставится отдельно, поэтому сбой стоит этого пакета, а не роутера |
| Пакет так и не встал | Сбой: конфликт файлов, зависимость, которой нет в фидах, или загрузка, которая не прошла за 4 попытки с паузами 2, 4 и 8 с (те же повторы, что у собственных загрузок owlab) |
| Имя не нашлось после обновления, где какой-то фид не ответил | Сбой: этот фид мог его нести. Исключение — когда не ответил только индекс kmods: в нём есть только пакеты `kmod-*` |

Пропуск имени, которого нет в фидах:

```
owlab: skip (not in this feed): luci-app-example
```

ImmortalWrt ставит `dnsmasq-full`, который даёт `dnsmasq`. Без пропуска opkg поставил бы рядом
настоящий `dnsmasq` и отказал бы на конфликте файлов:

```
owlab: skip (provided by dnsmasq-full, already installed): dnsmasq
```

При сбое:

- owlab печатает вывод менеджера пакетов, и сборка идёт дальше.
- Имя записывается на роутере в `/etc/owlab/packages-failed`.
- `owlab up` называет его после своей таблицы и выходит с кодом 1.
- `owlab test` проваливает этот роутер на шаге `packages`.

```
! owrt2410 is running WITHOUT luci-app-example
```

Обычный `owlab up` берёт сборку из кеша и сообщает те же имена снова. `owlab up --rebuild <router>`
собирает этот роутер с нуля.

## Пакеты, которых нет ни в одном фиде

`extra_packages:` ставит пакет по URL. Это для вашего собственного пакета и для всего, что опубликовано
на GitHub Releases. Всё, что есть в фидах OpenWrt, идёт в `packages:`.

```yaml
project:
  theme: footstrap          # активировать после установки

defaults:
  extra_packages:
    - name: luci-theme-footstrap
      apk: https://github.com/VizzleTF/luci-theme-footstrap/releases/download/v0.11.5/luci-theme-footstrap-0.11.5-r1.apk
      ipk: https://github.com/VizzleTF/luci-theme-footstrap/releases/download/v0.11.5/luci-theme-footstrap_0.11.5-r1_all.ipk
```

```console
$ owlab up
owlab: fetching https://github.com/VizzleTF/luci-theme-footstrap/releases/download/v0.11.5/luci-theme-footstrap-0.11.5-r1.apk
owlab: installing luci-theme-footstrap-0.11.5-r1.apk
  owrt2512   http://localhost:8025   ssh -p 2225 root@localhost
```

| Ключ | Что это | По умолчанию |
|---|---|---|
| `name` | Имя для сообщений и для скачанного файла | basename того URL, который используется |
| `apk` | URL для релизов с apk (25.12 и новее) | нет |
| `ipk` | URL для релизов с opkg (24.10 и старше) | нет |

- **Два URL.** Менеджеры не делят схему именования. Один и тот же релиз публикует
  `luci-theme-footstrap-0.11.5-r1.apk` и `luci-theme-footstrap_0.11.5-r1_all.ipk`.
- **Один на роутер.** owlab выбирает нужный и никогда не подсунет `.apk` коробке с 24.10. Любой из
  ключей можно опустить. Роутеру, у менеджера которого сборки нет, об этом скажут, и он поедет дальше.
- **Скачивание идёт на хосте** и кешируется в `.owlab/cache/`, так что `up` не тянет пакеты заново.
- **Качается только то, что нужно собираемым роутерам.** `owlab up owrt2512` скачивает пакеты и
  комплаенс-файлы owrt2512 и ничего для остальных роутеров из `owlab.yaml`. Пакет, который ставит
  только роутер на 24.10, его не уронит.
- **Повторы.** Загрузка, которая 60 секунд не присылает ни байта или обрывается на середине,
  начинается заново с первого байта, всего 4 попытки.
- **`--force-overwrite`.** Эти пакеты ставятся с ним. Без него один и тот же конфиг даёт на OpenWrt
  24.10 другой роутер, чем на остальных трёх.

**Подписи не проверяются.** Считайте всё, поставленное так, доверенным только по URL. Пиньте точный
релиз вместо ссылки на `latest` и не переносите этот приём никуда, что уезжает в продакшн.

### Когда дополнительный пакет не ставится

Провал здесь не проглатывается и не фатален:

1. Набор ставится целиком.
2. Если не вышло, owlab ставит по одному файлу, чтобы исправные всё-таки встали.
3. `owlab up` называет то, что так и не встало, после своей таблицы и выходит с ненулевым кодом.
   Лаборатория работает, но это не то, что описано в вашем конфиге.
4. `owlab test` на этом падает.
5. Имена остаются на роутере в `/etc/owlab/extras-failed`.

<details>
<summary>Почему на хосте, почему не фатально, зачем <code>--force-overwrite</code>, почему без подписей</summary>

Скачивать приходится на хосте: в стоковом rootfs нет `curl`, а его busybox `wget` не умеет TLS.

Имени из `packages:` в конкретном фиде может законно не быть. Эти пакеты названы по URL: вы сказали
«поставь этот файл», и об успехе без него owlab не отрапортует.

Сборку он тоже не уронит. Все роутеры лаборатории собираются в одном solve buildkit, и одна упавшая
цель отменяет остальные. Один пакет забрал бы с собой всю лабораторию.

Зависимости таких пакетов регулярно заменяют файл, которым уже владеет стоковый образ. Пакет,
зависящий от `dnsmasq-full`, тянет его за собой, а `dnsmasq-full` ставит `/etc/init.d/dnsmasq` и
сталкивается с `dnsmasq`.

Проекты, публикующиеся так, обычно подписывают usign и кладут `.sig` рядом. Проверка требует их
публичного ключа, а это решение о доверии, которое дев-контейнер не должен принимать за вас.

</details>

### Темам нужен ещё один шаг

Установка пакета темы её только *регистрирует*. Добавляется `luci.themes.<Name>`, а
`luci.main.mediaurlbase` остаётся нетронутым.

Задайте `project.theme`, и owlab активирует тему:

- при первой загрузке, после того как отработали собственные uci-defaults пакета;
- после каждого синка.

Значение — имя медиакаталога: `footstrap` для `/www/luci-static/footstrap`. Если такого каталога нет,
owlab пишет об этом в лог загрузки. `mediaurlbase` он в пустоту не направляет.

<details>
<summary>Зачем тему активировать</summary>

У пакета нет права менять то, на что смотрит пользователь. На дев-боксе это ровно наоборот: тема там
для того, чтобы на неё смотреть.

LuCI разрешает шаблоны через `mediaurlbase`, поэтому неверное значение роняет диспетчер.
Запасного варианта нет.

</details>

## Фикстуры

Профили фикстур выдумывают конфиг, с которым LuCI рисует секции, вкладки, таблицы, бейджи и формы.

```yaml
defaults:
  fixtures: [all]
```

| профиль | что добавляет |
|---|---|
| `networks` | WAN, гостевой бридж, два VLAN, выключенный интерфейс, статические маршруты, пулы DHCP, зоны файрвола и четырёхпортовую карточку «Port status» |
| `clients` | статические аренды, локальные имена хостов, а при загрузке — аренды DHCP и ARP-соседей, которые дают строки в таблицах данных |
| `portforwards` | проброс портов, один из них выключен |
| `system` | светодиоды, точки монтирования, swap, записи cron |
| `wireguard` | туннель wg0 с двумя пирами и его зону |
| `wifi` | радио, которые рисуются на коробке без радио |

| алиас | означает |
|---|---|
| `lived-in` | `networks clients portforwards system`. По умолчанию |
| `all` | все профили |
| `none` | голый роутер |

- Зависимости раскрываются автоматически: `fixtures: [portforwards]` получит ещё и `networks`.
- `wifi` включается отдельно, потому что забирает `/etc/config/wireless` целиком.
- **`wifi` на контейнере:** меню, строки радио, SSID, режимы и вся форма редактирования рисуются без
  какой-либо поддержки беспроводного в ядре. Сигнал, результаты сканирования и таблица подключённых
  станций остаются пустыми. Для них нужны настоящие радио, то есть `fidelity: vm`.
- **`wifi` на VM:** если настоящие phy есть, профиль удаляет выдуманный конфиг и запускает штатный
  `wifi config` против них.

**Ничто в фикстуре не имеет права трогать `lan`.** Это eth0 с адресом от движка, и это единственный
путь внутрь. Консоли, из которой можно спастись, нет. Каждая выдуманная сеть сидит на dummy-устройстве
или на VLAN, по которому не идёт трафик.

<details>
<summary>Зачем нужны фикстуры и как работает <code>wifi</code></summary>

Пустой роутер почти ничего не рисует. Секции, вкладки, таблицы, бейджи и формы, ради стилизации которых
существует тема или приложение, появляются только когда за ними есть конфиг. Контейнер с одним
интерфейсом и без клиентов показывает малую часть виджетов, и целый класс багов стилей на нём не
увидеть.

Беспроводные страницы LuCI почти целиком управляются конфигом. Меню появляется, когда существует
`/sbin/wifi`, список радио берётся прямо из UCI, а матрица возможностей шифрования строится вопросом к
бинарю `hostapd`, что он поддерживает.

На VM записать выдуманные секции было бы строго хуже, чем не делать ничего. netifd сопоставляет
`wifi-device` с phy по `path`. Выдуманные пути называют железо, которого нет. Настоящие радио остались
бы незанятыми, а LuCI рисовал бы строки для несуществующих радио.

</details>

## Пиньте точные точечные релизы

Пишите `release: "25.12.5"`, а не `"25.12"`. Rootfs и его фид обязаны называть один и тот же релиз.

- Пакетный менеджер записывает жёсткие пины (`base-files=1707~4ccb782af7` в `/etc/apk/world`). Rootfs
  25.12.4, направленный на фид 25.12.5, роняет любую установку с `breaks: world[...]`.
- owlab пинит фид к точному релизу, из которого пришёл rootfs. Старые точечные релизы остаются
  доступны в апстриме, так что это работает всегда.
- `release: "snapshot"` поддерживается, но не рекомендуется. Образы и фиды снапшота пересобираются
  ежедневно и независимо и расходятся в течение суток. `owlab doctor` об этом предупреждает.

## Готовые образы

Сборка роутера из апстримного rootfs занимает около минуты, бо́льшая часть — установка набора LuCI.
Старт с опубликованного образа занимает секунды:

```yaml
routers:
  - id: owrt2512
    release: "25.12.5"
    arch: x86_64
    image: ghcr.io/owfeed/owlab-rootfs:openwrt-25.12.5-x86_64
```

Всё остальное применяется поверх:

- ваши `packages:` ставятся (менеджер сообщает об уже установленных как об актуальных);
- фикстуры применяются заново;
- тема выбирается.

Готовый образ только ускоряет сборку, путь исполнения тот же. Ничто не ведёт себя иначе, чем с локально
собранным.

### Когда реестр не отвечает

Перед сборкой owlab спрашивает реестр образа, есть ли там образ: `HEAD` манифеста, который Docker Hub
не считает за pull.

| Реестр | Сервер загрузок | Результат |
|---|---|---|
| не отвечает (соединение отклонено, таймаут или 5xx либо 429 за 4 попытки) | есть rootfs-тарбол релиза | роутер собирается из тарбола, и owlab об этом пишет. Так и для образа по умолчанию, и для `image:` |
| сообщает, что тега нет (404), образ по умолчанию | есть тарбол | сборка из тарбола |
| сообщает, что тега нет (404), `image:` | любой | сборка падает: несуществующее имя, которое вы написали, — ошибка, которую надо исправить |
| не отвечает | тоже не отвечает | образ остаётся |

<details>
<summary>Почему тарбол — безопасная замена и почему без сети образ остаётся</summary>

В тарболе тот же rootfs, а путь через тарбол ничего не тянет ни из какого реестра.

Машина, которая не достаёт ни до того, ни до другого, работает без сети или выходит в интернет только
через собственный прокси или зеркало движка. Движок тогда ещё может скачать образ или собрать из образа
и слоёв, которые у него уже есть. Тарбол скачать нельзя совсем.

</details>

### Опубликованные теги

Теги — `<distro>-<release>-<arch>`:

```
ghcr.io/owfeed/owlab-rootfs:openwrt-25.12.5-x86_64
ghcr.io/owfeed/owlab-rootfs:openwrt-25.12.5-aarch64_generic
ghcr.io/owfeed/owlab-rootfs:openwrt-24.10.8-x86_64
ghcr.io/owfeed/owlab-rootfs:immortalwrt-25.12.1-x86_64
...
```

- **Плавающий тег.** Пересобирается еженедельно и подхватывает изменения фида внутри того же релиза.
- **Версионный тег.** Тег с суффиксом `-v0.1.0` сохраняет те же байты. Берите его, когда нужны те же
  байты дважды.
- **Один тег — одна цель.** Мультиархитектурного манифеста нет.
- **Происхождение.** Каждый образ несёт его в `/usr/share/owlab/compliance/`: манифест пакетов,
  CycloneDX SBOM с лицензиями по пакетам и файлы buildinfo, которые пинят дерево и каждый фид к точному
  коммиту.

<details>
<summary>Почему нет мультиархитектурного манифеста и зачем owlab кладёт комплаенс-файлы</summary>

В индексе образов OCI нет поля для «версии дистрибутива». У большинства имён архитектур OpenWrt
(`aarch64_generic`, `mips_24kc`) нет допустимого соответствия GOARCH, так что список манифестов эту
матрицу не выразит. Апстрим тоже не пытается.

Комплаенс-материал есть в апстриме, но *не* внутри rootfs. В тарболе нет ни текстов лицензий, ни
уведомлений об авторских правах. owlab собирает его при сборке, чтобы каждому пользователю ниже по
цепочке не пришлось восстанавливать его самому.

</details>

## Архитектура

`arch: auto` выбирает то, что работает нативно: `aarch64_generic` на Apple Silicon, `x86_64` на Intel и
AMD. Всё остальное идёт под эмуляцией: работает, но заметно медленно. `owlab doctor` предупреждает,
если вы её запросили.

| Архитектуры | Команды |
|---|---|
| `x86_64`, `i386_pentium4`, `aarch64_generic`, `arm_cortex-a15_neon-vfpv4`, `arm_cortex-a9_vfpv3-d16`, `mips_24kc`: target'ы, для которых upstream публикует rootfs | все команды |
| любая другая package-архитектура OpenWrt (`aarch64_cortex-a53`, `mipsel_24kc`, …) | только `owlab build` |

- `owlab build` идёт в `openwrt/sdk:<arch>-<release>`, который upstream привязывает к одной плате этой
  архитектуры. Userland-пакетам это не мешает, а модулям ядра другой платы — мешает.
- `up`, `test` и остальные команды, которые запускают роутер, отказывают такому роутеру с его именем.
  Без явных id они его пропускают.

```yaml
routers:
  - id: filogic
    release: "24.10.8"
    arch: aarch64_cortex-a53   # owlab build only
```

<details>
<summary>Почему другие архитектуры — только для сборки</summary>

Для реальных плат есть прошивки и SDK, но нет ничего, что можно поднять в контейнере или VM.

</details>

## Блокировки роутеров

`up`, `down`, `sync`, `test`, `install` и `exec` держат исключительную
блокировку на каждом роутере, с которым работают, до своего завершения. Вторая
сессия на том же роутере ждёт и печатает
`owlab: another session holds <FILE>; waiting for it`. `status`, `logs`,
`shell`, `open`, `build`, `releases` и `doctor` блокировку не берут. Своего таймаута у ожидания нет: его прерывает Ctrl-C, а в
`owlab test` оно входит в `--timeout`. `sync --watch` держит блокировки, пока
его не остановят. Блокировка снимается, когда процесс завершается, в том числе
аварийно, поэтому файл никогда не удаляют руками. На Linux и macOS это
flock(2), та же блокировка, что берёт `flock -x <FILE>`; на Windows —
LockFileEx.

| Имя | Тип | По умолчанию | Пример |
|---|---|---|---|
| `project.lock` | путь относительно каталога `owlab.yaml`; `{id}` — id роутера | `.owlab/locks/{id}.lock` | `lock: ../tmp/stands-{id}.lock` |
| `--no-lock` у `up`, `down`, `sync`, `test`, `install`, `exec` | флаг | выключен | `owlab sync owrt2512 --no-lock` |

Путь `project.lock` без `{id}` — одна блокировка на все роутеры. Команда,
которая работает с несколькими роутерами, берёт их блокировки в порядке путей.
С `--no-lock` команда не ждёт блокировку и не берёт её; у `exec` флаг
ставится до `--`. `OWLAB_NO_LOCK=1` в окружении действует так же на любую
команду. Скрипт, который уже держит общую блокировку, будет вечно ждать сам
себя, если запущенные им команды owlab её не пропустят, поэтому гейт задаёт
переменную один раз для всех:

```sh
flock -x ../tmp/stands-owrt2512.lock env OWLAB_NO_LOCK=1 <GATE_SCRIPT>
```

## Переменные окружения

На работающей машине не нужна ни одна. Каждая существует ради случая, который owlab не может
определить сам: установка в необычном месте или хост, у которого барахлит аппаратное ускорение.

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `OWLAB_CONFIG` | проект, с которым работать | поиск в рабочем каталоге и выше |
| `OWLAB_PUBKEY` | какие ssh-ключи ставить | все `~/.ssh/id_*.pub` |
| `OWLAB_ROOT_PASSWORD` | задать пароль root при сборке | пароля нет |
| `OWLAB_CACHE` | где лежат скачанные образы VM | пользовательский кеш |
| `OWLAB_QEMU` | бинарь `qemu-system-*`, которым грузиться | ищется сам, см. ниже |
| `OWLAB_QEMU_IMG` | `qemu-img` для создания дисков | тот, что лежит рядом с эмулятором |
| `OWLAB_FIRMWARE` | прошивка UEFI для VM на aarch64 или armv7 | ищется сама, см. ниже |
| `OWLAB_ACCEL` | задать акселератор принудительно, например `tcg` | самый быстрый на этом хосте |
| `OWLAB_NO_LOCK` | `1` пропускает блокировки роутеров, как `--no-lock`; см. [Блокировки роутеров](#блокировки-роутеров) | не задана |

- **`OWLAB_QEMU`** теперь нужен редко. owlab сам смотрит в PATH и в каталоги, куда кладут
  установщики: `C:\Program Files\qemu`, каталоги scoop и chocolatey на Windows, `/opt/homebrew/bin` на
  macOS. `owlab doctor` печатает, какой бинарь он выбрал.
- **`OWLAB_FIRMWARE`** нужна, только если поиск не нашёл файла. Несуществующий путь — ошибка. Без
  переменной owlab ищет в этих каталогах, по порядку:
  1. `../share/qemu` относительно бинаря QEMU, потом каталог самого бинаря (раскладка Windows);
  2. `/opt/homebrew/share/qemu`, `/usr/local/share/qemu`, `/usr/share/qemu`;
  3. `/usr/share/edk2/aarch64`, `/usr/share/edk2/arm`, `/usr/share/AAVMF`, `/usr/share/OVMF`.

  В каждом каталоге он пробует такие имена:

  | Архитектура | Имена файлов |
  |---|---|
  | `aarch64_generic` | `edk2-aarch64-code.fd`, `AAVMF_CODE.fd`, `QEMU_EFI.fd`, `QEMU_EFI-silent.fd` |
  | `arm_cortex-a15_neon-vfpv4` | `edk2-arm-code.fd`, `AAVMF32_CODE.fd`, `QEMU_EFI.fd` |

  `owlab doctor` печатает найденный файл как `vm firmware`.
- **`OWLAB_ACCEL=tcg`** — аварийный выход для хоста, где аппаратное ускорение не работает. Трансляция
  примерно на порядок медленнее и работает всегда.

<details>
<summary>Зачем нужен <code>OWLAB_ACCEL</code></summary>

На Windows это не теория. WHPX лежит поверх Hyper-V, и есть сообщения, что на одних машинах он вешает
SMP-загрузку, а на соседних работает.

</details>

## Флаги команд

Все флаги всех команд с дефолтами. `owlab <команда> -h` печатает флаги одной команды.

- **`--config <путь>` или `-c <путь>`** работает с любой командой, до или после её имени. Принимает
  файл или каталог, в котором он лежит. Без флага owlab читает `OWLAB_CONFIG`, потом ищет в рабочем
  каталоге и выше.
- **Id роутеров и флаги можно смешивать** в `up`, `down`, `sync`, `install`, `logs`, `status`, `test`,
  `shell` и `open`: `owlab up owrt2512 --rebuild` работает.
- **Без id роутеров** команда, которая умеет работать с несколькими, берёт все.
- **`build`, `releases`, `doctor` и `version`** принимают только флаги.
- **`--no-lock`** у `up`, `down`, `sync`, `install`, `exec` и `test` пропускает блокировку роутера: см.
  [Блокировки роутеров](#блокировки-роутеров).
- **У `exec` и `test`** свои разделы: [owlab exec](#owlab-exec) и [owlab test](#owlab-test).

### `owlab up`

`owlab up [роутеры...]` собирает и поднимает роутеры.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--rebuild` | собрать образы с нуля, мимо кеша слоёв | выключен |
| `--no-build` | поднять контейнерные роутеры из образов, которые уже есть у движка: собранных или загруженных через `docker load`. Ничего не скачивает и не собирает. См. [Запуск роутера из сохранённого образа](#запуск-роутера-из-сохранённого-образа) | выключен |
| `--no-wait` | вернуться сразу после старта контейнеров, не дожидаясь LuCI | выключен |
| `-v` | печатать выполняемые команды docker | выключен |

### `owlab down`

`owlab down [роутеры...]` останавливает роутеры.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--purge` | ещё и удалить собранные образы. У роутера `fidelity: vm` — ещё и его диски | выключен |
| `-v` | печатать выполняемые команды docker | выключен |

- **С id роутеров** останавливаются только они.
- **Без id** останавливается весь проект вместе с его сетью.
- **VM** просят выключиться самой. Без `--purge` на ней остаётся всё, что на неё поставили.

### `owlab sync`

`owlab sync [роутеры...]` копирует исходники проекта в запущенные роутеры. См.
[Что копирует `sync`](#что-копирует-sync-и-с-какими-правами).

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--watch` | не завершаться и синхронизировать заново при каждом изменении исходника | выключен |
| `--interval` | как часто проверять изменения при `--watch`, длительность в формате Go | `1s` |
| `--no-build` | пропустить `project.build` | выключен |
| `-v` | перечислить каждый синхронизированный файл | выключен |

### `owlab install`

`owlab install <роутер> <пакет>...` ставит пакеты на запущенный роутер. Путь к файлу на хосте,
например результат `owlab build`, сначала заливается на роутер. Всё остальное — имя из фида.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--all` | поставить на все роутеры. Тогда каждый аргумент — пакет | выключен |
| `--feed` | фид пакетов, который добавить сначала: для apk — URL индекса, для opkg — URL каталога. Нужен `--feed-key` | нет |
| `--feed-key` | файл с публичным ключом фида. Для opkg *имя файла* обязано быть key id | нет |
| `--feed-name` | под каким именем фид регистрируется | `owlab-feed` |
| `-v` | печатать выполняемые команды docker | выключен |

- **Id роутера** можно не писать, если в `owlab.yaml` один роутер.
- **Поставленное так исчезает после `owlab up --rebuild`.** `packages:` в `owlab.yaml` пересборку
  переживает.

### `owlab build`

`owlab build` собирает настоящий `.apk` или `.ipk` SDK OpenWrt, в образе
`openwrt/sdk:<target>-<release>`. Работает и с `owlab.yaml`, и без него.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--release` | релиз, под который собирать | релиз первого роутера, у которого не `fidelity: vm`. Без `owlab.yaml` обязателен |
| `--arch` | целевая архитектура. Подходит любая архитектура пакетов OpenWrt | архитектура того же роутера; без `owlab.yaml` — хостовая |
| `--out` | каталог для пакетов, относительно каталога проекта | `dist` |
| `--layout` | `arch` пишет в `<out>/<arch>/`; `flat` пишет всё в `<out>/` | `arch` |
| `--keep` | сохранить дерево сборки SDK в именованном томе Docker для следующего запуска. Имя — `owlab-sdk-<target>-<release>`, точки заменены дефисами | выключен |
| `-v` | показать полный лог сборки | выключен |

Что должно быть в проекте:

- **Makefile пакета OpenWrt** в каталоге проекта или в одном из его подкаталогов (на один уровень
  вниз, не скрытом). Каталог проекта — тот, где лежит `owlab.yaml`, а без него — рабочий каталог.
- **Makefile должен подключать** `$(TOPDIR)/rules.mk`, `luci.mk` или `package.mk`. Любой другой
  Makefile owlab пропускает.
- **Имя пакета** берётся из `PKG_NAME`. Без него берётся имя каталога, как это делает `luci.mk`.
- **Каталог архитектуры** берётся из `PKG_ARCH` или `LUCI_PKGARCH`. Без них — архитектура таргета.
  `all` и `noarch` пишут `noarch/` для apk и `all/` для ipk.

В конце сборки owlab перечисляет записанные файлы. Сборка, которая сообщила об успехе и не записала
ни одного пакета, выходит с кодом 1.

### `owlab logs`

`owlab logs [роутеры...]` показывает лог загрузки и сервисов роутера. Лог VM — её последовательная
консоль.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `-f` | следить за логом. За логом VM owlab следит, только когда выбран один роутер | выключен |
| `--tail` | сколько строк показать с конца | `all` |

### `owlab status`

`owlab status [роутеры...]` перечисляет роутеры и адреса, по которым до них достучаться.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--json` | вывести статус в JSON, схема `owlab.status/v1` | выключен |

### `owlab releases`

`owlab releases` сравнивает пины проекта с тем, что публикуют серверы загрузки. Движок контейнеров
ему не нужен. Без `owlab.yaml` выводит всё, как с `--all`.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--all` | перечислить все опубликованные релизы, а не только ветки этого проекта | выключен |
| `--keep` | с `--all`: сколько релизов показывать на ветку | `3` |
| `--json` | вывести ответ в JSON | выключен |

### `owlab shell`, `owlab open`, `owlab doctor`, `owlab version`

Флагов у них нет.

| Команда | Что делает |
|---|---|
| `owlab shell [роутер]` | открывает шелл на одном роутере. Id можно не писать, если в `owlab.yaml` один роутер |
| `owlab open [роутер]` | печатает URL LuCI одного роутера и открывает его в браузере |

| `owlab version` | печатает версию owlab. `owlab --version` и `owlab -v` делают то же самое |

### `owlab context`

`owlab context` нужен воркфлоу публикации образов, и в `owlab -h` его нет. Он пишет контекст сборки
одного роутера и печатает аргументы для `docker buildx build`.

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--router` | роутер, который подготовить. Обязателен, если нет `--list` | нет |
| `--release` | собрать этот релиз вместо запиненного в конфиге | запиненный |
| `--out` | каталог, куда писать контекст | `.owlab/publish` |
| `--list` | вывести роутеры JSON-матрицей для CI и выйти | выключен |
| `--keep` | с `--list`: сколько точечных релизов выдавать на ветку | `1` |

## owlab exec

`owlab exec <роутер> -- <команда>` выполняет команду на запущенном роутере. То, что идёт после `--`,
читается одним из двух способов — по числу слов:

| после `--` | выполняется как | пример |
|---|---|---|
| одно слово | шелл-скрипт, как написан | `owlab exec r -- 'ps \| grep uhttpd'` |
| два слова и больше | команда и её аргументы, каждый в кавычках | `owlab exec r -- sh -c 'exit 3'` |

- **Пайп, редирект или `;`:** возьмите всю команду в кавычки одним словом.
- **Оператор, набранный отдельным словом,** уходит команде как аргумент:
  `owlab exec r -- cat /etc/passwd '|' grep root` передаёт `|` команде `cat`.
- **Код выхода** — код самой команды.
- **stdin** передаётся дальше, если это пайп или файл. stderr остаётся в stderr.

## owlab test

Одна команда для CI: поднять роутеры, поставить пакет, проверить его на живом роутере, всё снести,
вернуть 0 или 1.

```console
$ owlab test --release 25.12.5 --release 24.10.8 \
    --install 'dist/*/luci-app-mine-*' \
    --assert 'http 200 /cgi-bin/luci/admin/services/mine'
```

| флаг | что делает |
|---|---|
| `--release` | по роутеру на релиз, вообще без `owlab.yaml`. Повторяемый, либо одно значение с несколькими: `--release "25.12.5 24.10.8"` |
| `--distro` | `openwrt` или `immortalwrt` для роутеров, созданных `--release` |
| `--arch` | архитектура для них; по умолчанию хостовая |
| `--packages` | пакеты для них; `+имя` добавляет к штатному набору |
| `--fixtures` | профили fixtures для них, например `none` или `all` |
| `--install` | путь (глобы раскрываются) заливается на роутер и ставится оттуда; всё остальное ищется в фидах. Повторяемый. Каждый роутер получает только тот формат, который читает его пакетный менеджер: `.apk` на 25.12+, `.ipk` на 24.10 и раньше — поэтому один глоб покрывает обе линии релиза. Пропущенный файл называется в строке install этого роутера |
| `--assert` | один ассершен, повторяемый. Каждый выполняется на каждом роутере |
| `--feed` | добавить фид пакетов до установки, чтобы имя разрешалось по подписанному индексу, а не из файла. Для apk — URL индекса, для opkg — URL каталога. Идёт вместе с `--feed-key` |
| `--feed-key` | файл с публичным ключом фида. Для opkg *имя файла* обязано быть key id — opkg ищет ключ именно по нему |
| `--feed-name` | под каким именем фид регистрируется на роутере; по умолчанию `owlab-feed` |
| `--sync` | сначала синхронизировать исходники, как `owlab sync`, вместо собранного пакета или вместе с ним |
| `--keep` | оставить роутеры поднятыми |
| `--rebuild` | собрать образы с нуля |
| `--json` | отчёт в stdout, всё остальное в stderr |
| `--timeout` | бюджет на весь прогон; по умолчанию 20m |
| `-v` | печатать выполняемые команды docker |

- **Без `--release`** роутеры берутся из `owlab.yaml`, и их id выбирают нужные — так же, как везде.
- **Снос** происходит и при успехе, и при падении, на собственном контексте.
- **Лог упавшего роутера** печатается до сноса, пока контейнер ещё существует.

<details>
<summary>Зачем сносу собственный контекст</summary>

Упавший прогон, оставивший контейнеры на портах 8080 и 2222, роняет *следующий* прогон по
постороннему поводу.

</details>

### Тест против фида, который вы раздаёте сами

Пишите `{host}` в URL `--feed`, и owlab подставит адрес хост-машины, верный для конкретного тира:

```sh
python3 -m http.server 8080 --directory out &
owlab test --release 25.12.5 \
  --feed 'http://{host}:8080/releases/25.12/noarch/packages.adb' \
  --feed-key out/keys/feed.pem \
  --install luci-app-mine \
  --assert 'http 200 /cgi-bin/luci/admin/services/mine'
```

URL без токена проходит нетронутым. Тот же флаг указывает на опубликованный фид без единой другой
правки.

<details>
<summary>Зачем ставить по имени и зачем <code>{host}</code></summary>

Установка собранного файла доказывает, что работает пакет. Установка *по имени* доказывает, что
работает канал: индекс парсится, URL не редиректит, ключ на роутере совпадает с тем, которым подписано.
Установка из файла так упасть не может, поэтому собственный CI фида хочет второго.

Значит, свежесобранное дерево надо раздать по HTTP с машины, где запущен owlab, и сообщить роутеру её
адрес. Адреса, который отвечает везде, не существует:

- контейнер на Linux-раннере достаёт хост через шлюз бриджа;
- под Docker Desktop такого шлюза нет вовсе;
- роутер `fidelity: vm` не видит ни того ни другого, потому что user-mode стек QEMU кладёт хост в
  третье место.

Обычный ответ — захардкодить `172.17.0.1`. Он ломается на первой же машине разработчика.

</details>

### Ассершены

| ассершен | проходит, когда |
|---|---|
| `http 200 /cgi-bin/luci/admin/services/mine` | страница отвечает этим статусом и не является страницей ошибки. `2xx` задаёт класс |
| `service mined` | так говорит `/etc/init.d/<имя> running` или ubus |
| `package luci-app-mine` | пакетный менеджер роутера считает его установленным |
| `uci mine.@mine[0].enabled` | значение задано. Так проверяется, что `uci-defaults` пакета отработали |
| `file /usr/share/rpcd/acl.d/luci-app-mine.json` | путь на роутере существует |
| `exec pgrep mined \| grep -q .` | команда завершилась с кодом 0 |

- Всё, кроме `http`, идёт через тот же транспорт, что `sync` и `exec`. Ассершены одинаково работают на
  контейнере и на роутере с `fidelity: vm`.
- `http` перед запросом логинится под root.
- Ещё `http` валит 2xx, в теле которого ошибка диспетчера («A runtime exception was caught», lua-шный
  `stack traceback:`).

<details>
<summary>Зачем <code>http</code> логинится и читает тело</summary>

Без сессии любая страница под `/cgi-bin/luci/admin` — редирект на форму логина. Из-за этого
написанный руками `curl -o /dev/null -w '%{http_code}'` показывает 403 на здоровой странице.

Поймав исключение, LuCI отвечает 200, и проверка одного статуса считает сломанную страницу здоровой.

</details>

### JSON-отчёт

`--json` кладёт отчёт в stdout и уводит в stderr всё остальное, включая вывод сборки docker.
`owlab test --json | jq` — это конвейер.

```json
{
  "schema": "owlab.test/v1",
  "owlab": "0.2.0",
  "project": "luci-app-mine",
  "ok": false,
  "routers": [
    {
      "id": "openwrt-24.10.8",
      "distro": "openwrt",
      "release": "24.10.8",
      "arch": "x86_64",
      "fidelity": "basic",
      "package_manager": "opkg",
      "luci": "http://localhost:8081",
      "ok": false,
      "steps": [
        { "check": "boot", "kind": "up", "ok": true, "seconds": 11.2 },
        { "check": "install luci-app-mine_1.0_all.ipk", "kind": "install", "ok": false,
          "detail": "* satisfy_dependencies_for: Cannot satisfy the following dependencies", "seconds": 3.1 }
      ]
    }
  ]
}
```

Другие команды с полем `schema`:

| Команда | `schema` | Что добавляет |
|---|---|---|
| `owlab status --json` | `owlab.status/v1` | имя контейнера и оба порта отдельно от URL |
| `owlab releases --json` | `owlab.releases/v1` | число `behind`: `jq '[.routers[].behind] \| add'` и есть весь ответ на «не устарело ли что-нибудь» |
| `owlab releases --json --all` | `owlab.releases.all/v1` | — |

### В GitHub Actions

```yaml
- uses: owfeed/owlab/action@v0.7.1
  with:
    releases: "25.12.5 24.10.8"
    install: dist/*/luci-app-mine-*
    assert: |
      http 200 /cgi-bin/luci/admin/services/mine
      service mined
```

- **Inputs, совпадающие с флагами.** `distro`, `arch`, `packages`, `fixtures`, `install`, `feed`,
  `feed-key`, `feed-name`, `assert`, `sync` и `timeout` называются как флаг. `--release` — это
  `releases`, список через пробел или запятую. `assert` и `install` принимают по одному значению на
  строку.
- **Input'а нет** для `--keep`, `--rebuild` и `-v`. Экшен всегда передаёт `--json` и пишет отчёт в
  файл.
- **Inputs самого экшена.** `routers` (id роутеров из `owlab.yaml` через пробел),
  `working-directory` (где искать `owlab.yaml`; по умолчанию `.`), `version`, `verify` (проверка
  attestation; по умолчанию `true`), `summary` (таблица в summary джоба; по умолчанию `true`) и `token`.
- **Outputs.** `report` (путь к JSON), `passed` и `failed`. Ещё экшен пишет таблицу в summary джоба.
- **Отдельный шаг setup не нужен.** Экшен ставит бинарь owlab сам, через тот же `setup/install.sh`,
  что и setup-экшен.
- **Только бинарь.** `owfeed/owlab/setup@v0.7.1` ставит только бинарь — для джоба, который сам
  вызывает `owlab`.
- **Проверка.** Оба проверяют скачанное по build attestation этого репозитория до того, как бинарь
  будет запущен или попадёт в `PATH`.
- **Версия.** Версия — это тег в `uses:`. `action@v0.7.1` и `setup@v0.7.1` ставят owlab v0.7.1,
  поэтому бамп этой строки от dependabot двигает и бинарь. `version:` задавайте, только если нужен
  другой релиз.
- **Ветка или SHA.** Вызванные по ветке или SHA, оба ставят последний релиз и предупреждают об этом.
- **Раннеры.** `ubuntu-latest` работает как есть. На macOS- и Windows-раннерах GitHub экшен прямо
  сразу говорит, что движка нет. Позже чем-то про сокет он не падает.

Готовый workflow лежит в [examples/workflow/package-ci.yml](../examples/workflow/package-ci.yml).

<details>
<summary>Почему не работают раннеры macOS и Windows</summary>

У macOS- и Windows-раннеров GitHub нет движка, запускающего линуксовые образы. Docker Desktop там не
установлен и не может быть установлен. Это свойство раннеров, owlab тут ни при чём: на собственной машине с macOS
или Windows, где движок установлен, работают все команды.

</details>

#### Запуск роутера из сохранённого образа

Джоб, который сам вызывает `owlab`, может один раз сохранить образ роутера и запускать из него
следующие джобы. Сборка роутера — это большая часть сетевой работы джоба: базовый образ, каждый пакет
из фидов, файлы `extra_packages`.

```console
$ mkdir -p ~/.cache/owlab-stand
$ docker save -o ~/.cache/owlab-stand/owrt2512.tar owlab-<project>-owrt2512:latest
$ docker load -i ~/.cache/owlab-stand/owrt2512.tar
$ owlab up --no-build owrt2512
```

`--no-build` ничего не качает и не собирает. Он запускает образ, который есть у движка, ждёт LuCI и
сообщает о недостающих пакетах так же, как обычный `owlab up`.

Он отказывается запускать:

- образ, чья метка `org.owlab.inputs` не совпадает с тем, что собрали бы этот owlab и этот
  `owlab.yaml`: образ от другого owlab, другого конфига роутера, другого `OWLAB_ROOT_PASSWORD` или
  собранный из rootfs-тарбола;
- образ без метки;
- роутер `fidelity: vm`, у которого образа нет.

Отказ из-за образа завершается с кодом 1 и называет `owlab up <id>`, который его соберёт. Скрипт может
перейти на эту команду.

Фиды метка не покрывает: сохранённый образ остаётся с пакетами, с которыми его собрали. Ключуйте кэш
датой, а не только `owlab.yaml` и версией owlab, чтобы ограничить, насколько роутер может устареть.
