# Справочник по конфигурации

[English](reference.md)

Все ключи `owlab.yaml`. «Как сделать X» — в [ранбуке](runbook_ru.md); почему
дефолты именно такие — во [внутренностях](internals_ru.md).

```yaml
version: 1

project:
  name: luci-theme-example        # по умолчанию имя каталога
  theme: example                  # для тем: активировать после sync
  install:                        # по умолчанию — маппинг из luci.mk
    htdocs: /www
    ucode:  /usr/share/ucode/luci
    luasrc: /usr/lib/lua/luci
    root:   /

defaults:                         # вливается в каждый роутер
  fidelity: basic
  arch: auto                      # совпадает с хостом, без эмуляции
  packages: ["+luci-app-sqm"]     # поверх стокового набора, см. ниже

routers:
  - id: owrt2512
    distro: openwrt               # openwrt | immortalwrt
    release: "25.12.5"
    packages: ["+luci-app-sqm"]   # + добавляет, - убирает
    ports: { http: 8025, ssh: 2225 }

  - id: real                      # только для fidelity vm:
    fidelity: vm
    release: "25.12.5"
    memory: 512M                  # qemu -m
    cpus: 2                       # qemu -smp
    disk: 2G                      # диск extroot; 0 — использовать свой оверлей образа
    radios: 2                     # радио mac80211_hwsim; 0 — без беспроводного
    ports: { http: 8090, ssh: 2290 }
```

Список пакетов с `+`/`-` применяется поверх дефолтов; список без префиксов их
заменяет.

## Стоковый набор пакетов

Роутер вообще без `packages:` — это не голый rootfs, а то, что установлено на
серийном устройстве с OpenWrt. Набор — собственные `DEFAULT_PACKAGES` и
`DEFAULT_PACKAGES.router` OpenWrt из `include/target.mk`, плюс то, что
firmware-selector добавляет для беспроводного роутера с LuCI:

```
base-files ca-bundle dropbear fstools libc libgcc logd mtd netifd uci
uclient-fetch urandom-seed urngd
dnsmasq firewall4 nftables kmod-nft-offload odhcp6c odhcpd-ipv6only ppp
ppp-mod-pppoe
wpad-basic-mbedtls wifi-scripts
luci luci-app-firewall luci-app-attendedsysupgrade luci-app-package-manager
```

Бо́льшая его часть уже есть в апстримном тарболе, так что установка обычно
ничего не делает. Перечисление всё равно имеет смысл: набор становится
свойством owlab, а не того тарбола, который дистрибутив решил опубликовать, — и
форк с более тощим rootfs получает тот же роутер.

Два осознанных отступления от списка реального устройства.

`libustream-mbedtls` не назван, хотя в апстримном списке он есть. TLS-бэкенд —
выбор времени сборки, а не фиксированное имя: в каждом образе уже есть тот
вариант, с которым он собран, и просьба к ImmortalWrt 24.10 поставить
mbedtls-вариант отклоняется.

Ничего платформенного: `fitblk`, `uboot-envtools`, `kmod-usb3`,
`kmod-leds-gpio`, `kmod-gpio-button-hotplug`, `kmod-crypto-hw-safexcel`,
`kmod-mt7915e` и прошивки mt7986 описывают разметку флеша, загрузчик,
светодиоды и радиокремний одной коробки. Без этого железа они не работают, а у
контейнера нет своего ядра, чтобы их загрузить. Добавляйте по одному, если
разрабатываемому пакету нужен файл на диске для разрешения зависимости.

Убрать что угодно через `-`:

```yaml
packages: ["-ppp", "-ppp-mod-pppoe", "+luci-app-sqm"]
```

Беспроводная пара в наборе не ради радио: LuCI гейтит всё меню
Network → Wireless на `access('/sbin/wifi')`, который приходит из
`wifi-scripts`, а матрицу шифрования строит, спрашивая у `hostapd`, что тот
поддерживает. С этими двумя страницы рисуются из конфига, без единого радио.

## Пакеты, которых нет ни в одном фиде

Почти всё, что нужно роутеру, лежит в фидах OpenWrt и идёт в `packages:`. Ваш
собственный пакет — нет, как и всё опубликованное на GitHub Releases. Для этого
есть `extra_packages:`:

```yaml
project:
  theme: footstrap          # активировать после установки

defaults:
  extra_packages:
    - name: luci-theme-footstrap
      apk: https://github.com/VizzleTF/luci-theme-footstrap/releases/download/v0.11.5/luci-theme-footstrap-0.11.5-r1.apk
      ipk: https://github.com/VizzleTF/luci-theme-footstrap/releases/download/v0.11.5/luci-theme-footstrap_0.11.5-r1_all.ipk
```

Два URL, потому что менеджеры не делят схему именования: один и тот же релиз
публикует `luci-theme-footstrap-0.11.5-r1.apk` и
`luci-theme-footstrap_0.11.5-r1_all.ipk`. owlab выбирает нужный под каждый
роутер и никогда не подсунет `.apk` коробке с 24.10. Любой из ключей можно
опустить; роутеру, у менеджера которого сборки нет, об этом скажут, и он
поедет дальше.

Скачивание идёт на хосте и кешируется в `.owlab/cache/`, так что `up` не тянет
их заново. Иначе и нельзя: в стоковом rootfs нет `curl`, а его busybox `wget` не
умеет TLS.

Провал здесь фатален, в отличие от имени из `packages:`, которого конкретный
фид может законно не иметь. Эти названы по URL — вы сказали «поставь этот файл»
— и сборка, отрапортовавшая успех без него, отдала бы вам роутер, тихо лишённый
того, против чего вы и тестируете. Ставятся с `--force-overwrite`, потому что их
зависимости регулярно заменяют файл, которым уже владеет стоковый образ:
`luci-app-openclash` тянет `dnsmasq-full`, который ставит `/etc/init.d/dnsmasq`
и сталкивается с `dnsmasq`.

**Подписи не проверяются.** Проекты, публикующиеся так, обычно подписывают
usign и кладут `.sig` рядом, но проверка требует их публичного ключа — а это
ровно то решение о доверии, которое дев-контейнер не должен принимать за вас.
Считайте всё, поставленное так, доверенным только по URL, пиньте точный релиз
вместо ссылки на `latest` и не переносите этот приём никуда, что уезжает в
продакшн.

### Темам нужен ещё один шаг

Установка пакета темы её только **регистрирует**: добавляется
`luci.themes.<Name>`, а `luci.main.mediaurlbase` остаётся нетронутым — у пакета
нет права менять то, на что смотрит пользователь. На дев-боксе это ровно
наоборот, поэтому `project.theme` выбирает тему после каждого sync.

## Фикстуры

Пустой роутер почти ничего не рисует: ни бейджей зон, ни VLAN, ни аренд DHCP,
ни таблиц со строками. Фикстуры всё это выдумывают.

```yaml
defaults:
  fixtures: [all]
```

Профили: `networks`, `clients`, `wireguard`, `portforwards`, `system`, `wifi`.
Алиас `lived-in` — всё, кроме wifi, и он же по умолчанию; `all` — всё; `none`
выключает. Зависимости раскрываются автоматически, так что
`fixtures: [portforwards]` получит ещё и `networks`.

Профиль `wifi` включается отдельно, потому что забирает `/etc/config/wireless`
целиком. На VM он ведёт себя иначе и проверяет, а не предполагает: если
настоящие phy есть, он удаляет выдуманный конфиг и запускает штатный
`wifi config` против них. Записать выдуманные секции там было бы строго хуже,
чем не делать ничего, — netifd сопоставляет `wifi-device` с phy по `path`, а
выдуманные пути называют железо, которого нет.

**Ничто в фикстуре не имеет права трогать `lan`.** Это eth0 с адресом от
движка, и это единственный путь внутрь; консоли, из которой можно спастись,
нет. Каждая выдуманная сеть сидит на dummy-устройстве или на VLAN, по которому
не идёт трафик.

## Пиньте точные точечные релизы

Rootfs и его фид обязаны называть один и тот же релиз. apk записывает жёсткие
пины в `/etc/apk/world` (`base-files=1707~4ccb782af7`), поэтому rootfs 25.12.4,
направленный на фид 25.12.5, роняет любую установку с `breaks: world[...]`.

Не пиньте `snapshot`: образы и фиды снапшота пересобираются ежедневно и
независимо, так что расходятся в течение суток. `owlab doctor` об этом
предупреждает.

## Готовые образы

```yaml
routers:
  - id: fast
    image: ghcr.io/owfeed/owlab-rootfs:openwrt-25.12.5-x86_64
```

Всё остальное применяется поверх: пакеты ставятся (менеджер сообщает об уже
установленных как об актуальных), фикстуры применяются заново, тема
выбирается. Готовый образ — ускоритель, а не другой путь исполнения.

Плавающий тег пересобирается еженедельно и подхватывает изменения фида внутри
того же релиза. Когда нужны те же байты дважды, берите версионный тег с
суффиксом `-v0.1.0`.

## Архитектура

`arch: auto` — по умолчанию, подбирается под хост: `aarch64_generic` на arm64,
`x86_64` на amd64. Явное значение из списка поддерживаемых тоже можно, но
`owlab doctor` предупредит, что не родная хосту архитектура идёт под эмуляцией.

## owlab test

Одна команда для CI: поднять роутеры, поставить пакет, проверить его на живом
роутере, всё снести, вернуть 0 или 1.

```console
$ owlab test --release 25.12.5 --release 24.10.8 \
    --install 'dist/*/luci-app-mine-*.apk' \
    --assert 'http 200 /cgi-bin/luci/admin/services/mine'
```

| флаг | что делает |
|---|---|
| `--release` | по роутеру на релиз, вообще без `owlab.yaml`. Повторяемый, либо одно значение с несколькими: `--release "25.12.5 24.10.8"` |
| `--distro` | `openwrt` или `immortalwrt` для роутеров, созданных `--release` |
| `--arch` | архитектура для них; по умолчанию хостовая |
| `--packages` | пакеты для них; `+имя` добавляет к штатному набору |
| `--fixtures` | профили fixtures для них, например `none` или `all` |
| `--install` | путь (глобы раскрываются) заливается на роутер и ставится оттуда; всё остальное ищется в фидах. Повторяемый |
| `--assert` | один ассершен, повторяемый. Каждый выполняется на каждом роутере |
| `--feed` | добавить фид пакетов до установки, чтобы имя разрешалось по подписанному индексу, а не из файла. Для apk — URL индекса, для opkg — URL каталога. Идёт вместе с `--feed-key` |
| `--feed-key` | файл с публичным ключом фида. Для opkg *имя файла* обязано быть key id — opkg ищет ключ именно по нему |
| `--feed-name` | под каким именем фид регистрируется на роутере; по умолчанию `owlab-feed` |
| `--sync` | сначала синхронизировать исходники, как `owlab sync`, вместо собранного пакета или вместе с ним |
| `--keep` | оставить роутеры поднятыми |
| `--rebuild` | собрать образы с нуля |
| `--json` | отчёт в stdout, всё остальное в stderr |
| `--timeout` | бюджет на весь прогон; по умолчанию 20m |

Без `--release` роутеры берутся из `owlab.yaml`, и их id выбирают нужные — так
же, как везде.

Снос происходит и при успехе, и при падении, на собственном контексте: упавший
прогон, оставивший контейнеры на портах 8080 и 2222, роняет *следующий* прогон
по постороннему поводу. Лог упавшего роутера печатается до этого, пока контейнер
ещё существует.

### Тест против фида, который вы раздаёте сами

Установка собранного файла доказывает, что работает пакет. Установка *по имени*
доказывает, что работает канал: индекс парсится, URL не редиректит, ключ на
роутере совпадает с тем, которым подписано. Установка из файла так упасть не
может — поэтому собственный CI фида хочет второго.

Значит, свежесобранное дерево надо раздать по HTTP с машины, где запущен owlab, и
сообщить роутеру её адрес. Адреса, который отвечает везде, не существует:
контейнер на Linux-раннере достаёт хост через шлюз бриджа, под Docker Desktop
такого шлюза нет вовсе, а роутер `fidelity: vm` не видит ни того ни другого,
потому что user-mode стек QEMU кладёт хост в третье место. Обычный ответ —
захардкодить `172.17.0.1` — ломается на первой же машине разработчика.

Пишите `{host}`, и owlab подставит верное для конкретного тира:

```sh
python3 -m http.server 8080 --directory out &
owlab test --release 25.12.5 \
  --feed 'http://{host}:8080/releases/25.12/noarch/packages.adb' \
  --feed-key out/keys/feed.pem \
  --install luci-app-mine \
  --assert 'http 200 /cgi-bin/luci/admin/services/mine'
```

URL без токена проходит нетронутым — тот же флаг указывает на опубликованный фид
без единой другой правки.

### Ассершены

| ассершен | проходит, когда |
|---|---|
| `http 200 /cgi-bin/luci/admin/services/mine` | страница отвечает этим статусом и не является страницей ошибки. `2xx` задаёт класс |
| `service mined` | так говорит `/etc/init.d/<имя> running` или ubus |
| `package luci-app-mine` | пакетный менеджер роутера считает его установленным |
| `uci mine.@mine[0].enabled` | значение задано — так проверяется, что `uci-defaults` пакета действительно отработали |
| `file /usr/share/rpcd/acl.d/luci-app-mine.json` | путь на роутере существует |
| `exec pgrep mined \| grep -q .` | команда завершилась с кодом 0 |

Всё, кроме `http`, идёт через тот же транспорт, что `sync` и `exec`, поэтому
ассершены одинаково работают на контейнере и на роутере с `fidelity: vm`.

`http` перед запросом логинится под root: без сессии любая страница под
`/cgi-bin/luci/admin` — редирект на форму логина, из-за чего написанный руками
`curl -o /dev/null -w '%{http_code}'` показывает 403 на здоровой странице. Ещё
он валит 2xx, в теле которого ошибка диспетчера («A runtime exception was
caught», lua-шный `stack traceback:`): поймав исключение, LuCI отвечает 200, и
проверка одного статуса считает сломанную страницу здоровой.

### JSON-отчёт

`--json` кладёт отчёт в stdout и уводит в stderr всё остальное, включая вывод
сборки docker, — так что `owlab test --json | jq` это конвейер.

```json
{
  "schema": "owlab.test/v1",
  "owlab": "0.2.0",
  "project": "luci-app-mine",
  "ok": false,
  "routers": [
    {
      "id": "openwrt-24.10.8",
      "distro": "openwrt",
      "release": "24.10.8",
      "arch": "x86_64",
      "fidelity": "basic",
      "package_manager": "opkg",
      "luci": "http://localhost:8081",
      "ok": false,
      "steps": [
        { "check": "boot", "kind": "up", "ok": true, "seconds": 11.2 },
        { "check": "install luci-app-mine_1.0_all.ipk", "kind": "install", "ok": false,
          "detail": "* satisfy_dependencies_for: Cannot satisfy the following dependencies", "seconds": 3.1 }
      ]
    }
  ]
}
```

У `owlab status --json` и `owlab releases --json` тоже есть поле `schema`
(`owlab.status/v1`, `owlab.releases/v1`, и `owlab.releases.all/v1` для `--all`).
`status` добавляет имя контейнера и оба порта отдельно от URL; `releases` —
число `behind`, так что `jq '[.routers[].behind] | add'` и есть весь ответ на
«не устарело ли что-нибудь».

### В GitHub Actions

```yaml
- uses: owfeed/owlab/action@v0.5.0
  with:
    releases: "25.12.5 24.10.8"
    install: dist/*/luci-app-mine-*.apk
    assert: |
      http 200 /cgi-bin/luci/admin/services/mine
      service mined
```

У каждого флага выше есть одноимённый input; `assert` и `install` принимают по
одному значению на строку. Экшен пишет таблицу в summary джоба и отдаёт outputs
`report` (путь к JSON), `passed` и `failed`. `owfeed/owlab/setup@v0.5.0`
ставит только бинарь — для джоба, который сам вызывает `owlab`. Оба проверяют
скачанное по build attestation этого репозитория до того, как бинарь будет
запущен или попадёт в `PATH`.

`ubuntu-latest` работает как есть. У macOS-раннеров GitHub нет никакого движка
контейнеров, и экшен говорит об этом прямо, а не падает позже чем-то про сокет.

Готовый workflow лежит в
[examples/workflow/package-ci.yml](../examples/workflow/package-ci.yml).

## Лицензия и товарные знаки

owlab распространяется под GPL-2.0-only.

OpenWrt — зарегистрированный товарный знак Software Freedom Conservancy. owlab
не аффилирован с проектом OpenWrt или SFC и ими не одобрен; название OpenWrt
используется только для указания на то, с чем этот инструмент работает.

Образы, собранные owlab, содержат неизменённое ПО OpenWrt или ImmortalWrt,
лицензированное GPL и другими лицензиями их собственными авторами.
